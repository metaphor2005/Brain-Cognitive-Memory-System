> 持续更新。每次遇到的问题都按「现象 → 原因 → 解决 → 教训」记一条，
> 方便回头查同类坑，也避免同一个错误再犯一遍。

## 2026-11-19 · 生命周期与遗忘

### 1. 衰减/遗忘永远淘汰不掉旧信念

- **现象**：「生命周期遗忘与恢复」测试失败，旧信念强度降不下去。
- **原因**：`_set_state` 在衰减时把 `last_access_ts` 刷成当前时间，强度公式里的年龄归零，
  强度立刻回到 1.0。
- **解决**：衰减/遗忘时**不刷新** `last_access_ts`，只有 `restore` 才刷新。
- **教训**：刷新"最后访问时间"是一个看起来无害、实际会重置整条衰减曲线的副作用。

### 2. 白名单设计过窄，中文关系名全部漏判

- **现象**：3 个测试失败——"我改主意了"的推翻功能完全失效，旧值一直留着。
- **原因**：初版定的是"单值白名单，名单外默认共存"，但名单里全是英文
  （`live_in`/`birthday`…），系统实际用的关系名多是中文（"策略"/"喜欢"），
  全部落到"名单外"，于是全被当成多值共存。
- **解决**：把名单**反过来用**——默认单值（新值替换旧值），名单只放明确多值的关系
  （室友/朋友/喜欢…）做兜底，并优先信模型自己给的 `multi` 标记。
- **教训**：问题不在"用英文还是中文"，而在"靠穷举名字判断"这个思路本身。
  动态生成的数据不能靠写死名单去穷举。

## 2026-11-19 · 冲突置信度与读路径

### 3. `query_by_text` 有两个同名定义，后者遮蔽前者

- **现象**：上一轮加的 lifecycle 过滤"测试通过但实际没生效"。
- **原因**：文件里有两个同名方法，Python 只保留后定义的那个；过滤加在了前面的死代码上。
  测试之所以过，是因为遗忘时 `is_active=0` 顺带过滤掉了，掩盖了问题。
- **解决**：合并成单一实现，保留过去时检索、相关性打分和 lifecycle 过滤。
- **教训**：测试通过不等于代码生效。改完要看一眼"改的是不是真正被调用的那个"。

### 4. `_relevance` 里局部变量覆盖函数参数

- **现象**：相关性打分永远满分，等于没打分。
- **原因**：函数内部用 `text` 拼出行内文本，把表示用户查询的同名参数覆盖了，
  于是变成"拿这行文字去匹配它自己"。
- **解决**：重命名变量，明确用用户查询文本做比对。
- **教训**：`text` 这种泛泛的变量名容易撞车，参数名要具体（`query_text`）。

### 5. 多值判定误杀旧值

- **现象**：同一个人有两个室友时，旧室友被当成冲突关掉。
- **原因**：生产路径完全信模型的 `multi` 标志，模型漏标就误杀。
- **解决**：加 `BELIEF_MULTI_VALUE_RELS` 兜底白名单，白名单外沿用模型标志。
- **教训**：模型输出要留人工/配置兜底，不能假设它每次都对。

## 2026-11-19 · 并发与安全

### 6. `TaskStore.create()` 几乎必然返回 `None`

- **现象**：并发测试里任务创建后取不回来。
- **原因**：插入时生成一个随机 id，返回时又生成另一个——两个 id 不一样，
  按第二个去查自然查不到。
- **解决**：id 只生成一次，复用同一个变量。
- **教训**：凡是"生成后要回查"的 id，必须只生成一次。

### 7. `random.randint(1000, 9999)` 做并发 id

- **现象**：并发创建 40 个任务有碰撞风险。
- **原因**：只有 9000 种可能，并发下必然撞。
- **解决**：改用现成的 `new_id("task")`（uuid4）。
- **教训**：id 生成器不要自己造轮子。

### 8. SQL 占位符与参数数目不匹配

- **现象**：`ProgrammingError: 8 placeholders but 9 supplied`。
- **原因**：`insert` 少了一个占位符，参数里却多传了一个。
- **解决**：对齐 SQL 与参数，去掉多余参数。
- **教训**：这类 bug 一调用就炸，反而好查；埋在没覆盖的代码里才是隐患。

### 9. `database.py` 缺 `import json`

- **现象**：`NameError: name 'json' is not defined`。
- **原因**：`TaskStore` 用了 `json.dumps` 但文件顶部没导入。
- **解决**：补 `import json`。
- **教训**：只有真的执行到那段代码才会暴露——再次说明"没测到的分支等于没写"。

### 10. 限流字典无锁

- **现象**：多线程并发时"检查-追加"不是原子操作，请求可同时超限。
- **原因**：共享 dict 没有任何同步。
- **解决**：加 `_RATE_LOCK`，把逻辑抽成可离线测试的纯函数 `_rate_limit`。
- **教训**：共享可变状态 + 多线程 = 必须上锁；抽纯函数让并发行为也能被测试。

## 2026-11-19 · Optional work（5 项）

### 11. 正常生产路径的归档必崩：`_SELF_SHAPING_HINTS` 未定义

- **现象**：回放 harness 第一次运行就抛
  `NameError: name '_SELF_SHAPING_HINTS' is not defined`。
- **原因**：`archiver._persona_update_allowed` 用了这个常量，但全项目从未定义它。
  现有 smoke 测试全部传 `client=None`，抽取阶段就走降级分支提前 return，
  恰好绕过了这行——所以测试全绿，真实配了模型却每次归档都崩。
- **解决**：补上常量定义（"你希望/你觉得/你的定位…"等自我塑造线索），并加了
  走真实客户端路径的回放测试。
- **教训**：**测试全绿只能证明被测到的路径是好的**。要有意识地加一条"走真实依赖"
  的测试，否则降级分支会形成巨大的盲区。这是本轮最有价值的发现。

### 12. Windows 临时目录清理失败

- **现象**：回放脚本抛异常后，`TemporaryDirectory` 清理时报
  `PermissionError: 另一个程序正在使用此文件: replay.db`。
- **原因**：SQLite 连接没关，Windows 不允许删除仍被句柄占用的文件。
- **解决**：在 `with TemporaryDirectory()` 内部用 `try/finally` 调
  `db.close_all_connections()`，确保退出前释放句柄。
- **教训**：Windows 上临时数据库一定要显式关连接；Linux 能删是因为允许删已打开文件。

### 13. 回放用例把好感对象写成人格自己

- **现象**：golden 快照里 `affection` 一直是空的，看不到好感变化。
- **原因**：用例里把好感对象写成"江秀妍"（人格本人），系统按设计跳过了"对自己的好感"。
- **解决**：换成别人（林夏），快照里就有了完整的好感轨迹和主动消息。
- **教训**：这是**用例写错**而不是代码 bug——但 golden 快照帮我们立刻看出了异常。
  写测试数据时要注意系统已有的业务规则。

### 14. API health 断言过强

- **现象**：`health 应豁免令牌` 测试失败。
- **原因**：测试断言 `/api/health` 返回 200，但本机没模型密钥时它返回 500。
- **解决**：只断言"非 401"——要验证的是鉴权豁免，不是服务健康。
- **教训**：断言要精确对应测试目的，别顺带断言无关的东西。

## 2026-11-19 · 多进程共享限流

### 15. SQLite 限流器缺 `row_factory`，按列名取值报 TypeError

- **现象**：新增的「限流 SQLite 后端」测试异常
  `TypeError: tuple indices must be integers or slices, not str`。
- **原因**：`rate_limit_store.py` 的 `sqlite3.connect()` 没设 `row_factory`，
  `fetchone()` 返回的是 tuple，代码却用 `row["cnt"]` 按列名取。这与问题 #9 所在文件
  `database.py` 里早就处理过（那里显式设了 `sqlite3.Row`）是同一类坑。
- **解决**：连接创建后补 `connection.row_factory = sqlite3.Row`。
- **教训**：只要是"按列名读 SQLite 结果"，连接就必须设 row_factory；新写一个存储类时
  要对照已有 `Database` 的标准配置，别重新发明连接初始化。

## 2026-11-19 · 情绪像人（状态→语言的最后一公里）

### 16. 新增情绪字段后，固定回放 golden 失配

- **现象**：「固定对话回放」失败，diff 显示第 3 轮「关系转冷」的 report 多了两个字段
  `emotion_events: ["relation_cold"]` 与 `emotion_activated: {"hurt": 0.5}`。
- **原因**：这次给归档报告加了情绪事件记录，golden 是旧快照，自然对不上。
- **解决**：先逐字段确认 diff **正是预期变更**（只有这两个新字段，其余完全一致），
  再用 `dialogue_replay.py --record` 重录，紧接着跑一次无参数回放确认一致。
- **教训**：golden 失配不能直接 `--record` 覆盖——要先读懂 diff，确认不是把 bug 录进基线。
  回放在这里的价值是"逼你确认每次状态变更是不是有意为之"。

### 17. 测试注册写了不存在的符号名

- **现象**：想把新测试加进两个测试列表时，`edit` 找不到 `test_persona_baseline_resist`。
- **原因**：凭印象记错了符号名，实际函数叫 `test_persona_baseline`
  （"抗漂移"只是测试列表里显示的中文名，不是函数名）。
- **解决**：先 `grep` 确认真实符号名与两处行号，再用 `replaceAll` 一次注册两处。
- **教训**：注册测试前先核对符号名；这个文件有两个 `main()`、两个测试列表，
  新测试必须两处都加（第二个才是实际入口），用 `replaceAll` 避免漏掉一处。

## 2026-11-19 · 久别重逢（时光流逝的反应）

### 18. 真调 `chat()` 会在第一行就崩：`new_id` 从未导入（同类生产 bug）

- **现象**：写"隔三天再开口"的链路测试（第一次真正调用 `CognitiveAgent.chat()`）时，
  预感它会暴露问题——查发现 `engine.py:220` 用了 `new_id("turn")`，但整个文件
  **没有导入 `new_id`**（定义在 `cognitive/models.py:24`）。只要真走 `chat()` 必然 `NameError`。
- **原因**：和问题 #11（`_SELF_SHAPING_HINTS`）完全一样——现有测试大量用 `client=None`
  或只调 `MemoryArchiver.archive`，回放 harness 也只走归档，从不走 `chat()`，
  于是这个"主链路入口"的 bug 一直被降级/绕过的测试掩盖。
- **解决**：`engine.py` 从 `cognitive.models` 补导入 `new_id`。
- **教训**：**第二次印证"测试全绿只证明被测路径没问题"**。任何"主入口函数"
  （这里是 `chat()`）都该有一条真正调用它的测试——否则最核心的路径反而是盲区。

### 19. Prompt 字符串里的中文引号写成了 ASCII 引号，语法直接崩

- **现象**：新增重逢渲染函数后 `py_compile` 报
  `SyntaxError: invalid character '…' (U+2026)`，指向字符串中间的省略号。
- **原因**：f-string 里想写「好久不见」「最近怎么样」这类带引号的示例，
  写入时引号变成了 ASCII `"`，提前结束了字符串，后面的 `…` 落在字符串外。
- **解决**：把内层引号统一改成中文书名号「」，不再和 Python 的字符串分隔符冲突。
- **教训**：Prompt 文本里嵌中文引号示例时，一律用「」/『』，别用 ASCII 引号；
  写完立刻 `py_compile`，别等跑测试才发现的低级语法错。

### 20. `long_hours` 单位写错：传了秒当小时

- **现象**：「久别重逢」测试里"长间隔用好久不见语气"断言失败。
- **原因**：`render_reunion_block` 的参数 `long_hours`/`min_hours` 单位是**小时**，
  测试里却传了 `7 * 86400`（那是秒），导致比较永远不成立、走了短间隔分支。
- **解决**：测试改成 `7 * 24`（小时）。
- **教训**：带单位的参数名（`*_hours`/`*_seconds`/`*_ms`）要在测试里按单位换算，
  拿到门槛先确认单位，别凭数字大小直觉判断。

## 2026-11-19 · 专项审查（收尾时回头查缺陷）

> 功能做完不急着加新东西，先回头把今天的改动从头审一遍。以下是审查揪出的问题，
> 其中几条是"测试全绿但真实行为不对"的典型。

### 21. 重逢区块把"本轮召回的话题"说成"上次聊的"（编造记忆）

- **现象**：`engine.py` 用 `memory.topics[0].title` 当"上次聊的话题"，而这来自
  **当前用户消息**的向量检索，跟"上次互动那轮聊了什么"毫无关系。
- **原因**：把"相关的话题"误当成"上次的话题"。隔三天回来问个无关问题，
  Prompt 会断言一个假的"上次你说…"，直接违反系统自己的思考纪律第 7 条"不要编造"。
- **解决**：改用上一轮最后一条消息的 `turn_id`，经 `get_topic_by_turn` 查**真实归档记录**；
  查不到就不带这个话题。同时把时间锚点从 `context.update_ts` 改成最后一条消息的 `ts`
  （不受压缩路径刷写影响）。
- **教训**：任何"上次/之前/你曾经…"的措辞都必须有真实记录撑腰；"相关"不等于"上次"。

### 22. 函数内重复 import 遮蔽顶部导入，异常被吞导致静默失效

- **现象**：修 #21 后重逢测试失败，日志却看不到原因——只显示"没触发重逢区块"。
- **原因**：`chat()` 内部第 478 行还有一次 `from ... import TopicStore`，让 `TopicStore`
  在整个 `chat()` 作用域里变成局部变量；我在它之前（312 行）使用，触发
  `UnboundLocalError`。而重逢区块包在 `try/except` 里，异常被吞成"降级为空"，
  测试只看到空区块，看不到底层报错。
- **解决**：删掉函数内那处冗余 import（模块顶部已导入）。
- **教训**：① Python 里函数内任意位置 import 一个名字，会让它在整个函数里变成局部变量；
  ② "降级为空"的 try/except 必须同时把原因写进 `debug["error"]`，否则静默失败极难排查。

### 23. 情绪措辞重复 + 上报名义强度 + 事件误报

- **现象**：审查发现三处"不算崩但不对"的行为：
  1. `describe()` 仍为 5 个认知态输出"强度 0.75"的裸数字行，和新情绪区块重复，
     且阈值写死 0.3（与新配置不一致）；
  2. `react_to_events` 上报映射表里的名义值：已有 hurt 0.9 时再触发冷落(0.5)，
     库里仍是 0.9，报告却写 0.5；
  3. 任何信念冲突（哪怕"谁生日改期"这种琐事）都触发 hurt+自省，"更像人"变成"对什么都委屈"。
- **原因**：新功能接在旧机制上时，没检查旧路径是否还在做同一件事；上报用了"意图值"而非"结果值"；
  事件触发没复用已有的 `is_core_belief` 重要性门槛。
- **解决**：① `EMOTION_SPEECH_ENABLED` 开启时 `describe()` 不再输出裸数字行（关闭时保留旧行为供 A/B）；
  ② 上报改从 `get_moods()` 重建，只含本次触及的情绪、值为实际写入强度；
  ③ `belief_overturned` 收进 `is_core_belief` 门槛并去重。
- **教训**：加新层时要检查旧层是否重复输出；上报值要取"落库后的真实值"而非"传进去的意图值"；
  情感反应要挂在已有的重要性门槛上，别对琐事滥情。

### 24. 新配置未校验、运行时开关会破坏数值配置

- **现象**：`REUNION_LONG_HOURS < REUNION_MIN_HOURS`、强度门槛 >1、或环境变量填了 `nan`,
  都会让功能静默失效而不报任何错；`apply_runtime_toggles` 还会把误填进 UI 的数值键
  用 `bool()` 变成 True/False。
- **原因**：新增配置项没纳入 `validate_config()`；运行时开关对所有键一律 `bool(value)`。
- **解决**：`validate_config()` 加有限性与区间校验（含 `math.isfinite` 挡 nan）；
  `apply_runtime_toggles` 只对当前值是 bool 类型的键做覆盖。
- **教训**：配置即代码——每个新配置都要有合法性校验，否则错误配置的表现是"功能悄悄没了"。

### 25. 情绪增强项缺异常保护，失败会造成"报告失败但库里半份归档"

- **现象**：步骤 8 的 `decay_moods()/react_to_events()` 没有 try/except；一旦抛异常，
  前面已落的 topic/KG/向量不会回滚，但报告被吞成 `ok=False`。
- **原因**：情绪是后来加的增强项，没按"增强项一律可降级"的既有约定处理。
- **解决**：步骤 8 包 try/except，失败写 `emotion_degraded` 并继续；
  `engine` 步骤 4 的情绪渲染也加了同类降级。
- **教训**：新增环节必须遵守"增强项失败不拖垮主链路"——要么可降级，要么别加。

## 设计来源（每个决定是怎么来的）

> 和上面的「问题」互补：上面记「哪里错了」，这里记「当初为什么这么定」。
> 文献编号对应 `docs/REFERENCES.md`；没有文献的地方，写明是工程约束还是踩坑后反推。

### A. 总体取舍

| 设计决定 | 来源 | 理由 / 代价 |
|---|---|---|
| 零第三方依赖、单机 SQLite、不用 Redis/Celery | 工程约束（本地单用户、Windows、`py` 3.12、装了就要能跑） | 部署简单、数据全在本地；代价是水平扩展要自己写 worker，且限流状态必须先落 SQLite 才能跨进程生效 |
| 破坏性操作默认 dry-run，显式 `apply` 才执行 | [43] 幂等 API、[54] 机器遗忘 + 工程约束 | 遗忘/删除先给你看清单，确认后再动手，避免误操作；代价是多一次确认 |
| 遗忘 = 逻辑状态变更，不物理删除 | [11] 类人遗忘、[54][55] 遗忘基准 + 本地隐私需求 | 保留来源、审计账本（`memory_lifecycle_event`），可恢复；代价是查询要带 `lifecycle_state` 过滤 |
| 强表达 / 断交剧情默认 opt-in、显式运行 | [63][64]  AI 陪伴的情感风险 | 系统不该擅自对用户"翻脸"；做成手动脚本，永不进后台调度 |

### B. 记忆与检索

| 设计决定 | 来源 | 理由 / 代价 |
|---|---|---|
| 默认 TF-IDF（中文字符 2-gram），不用外部 embedding | [7][8][9] 分层/图检索思路 + 工程约束：DeepSeek 无 embedding 接口、本地模型体积大 | 完全离线、可解释、零依赖；代价是 recall 上限低于稠密向量（当前 Recall@1=0.952） |
| Embedding 做成可选后端，缺依赖自动回退 TF-IDF | [7][8][9] + 实测（本轮验证缺 `sentence-transformers` 时指标不变） | 想升级时开一个配置即可，默认安装不受影响 |
| 检索与否交给判决器（按需 RAG），而不是每轮都检索 | [25] RAG、[26] Self-RAG、[27] CRAG | 已有信息够就别翻记忆，省 token 也避免引入噪声 |
| 短期窗口 50 轮 + 兜底压缩 | [47][48] 工作记忆容量、[51] Lost in the Middle | 上下文太长会被模型"看丢"，保留近期对话即可 |
| 相关性 `_relevance` 做二次打分 | 问题记录 #4（实测打分永远满分） | 不能只信向量分数，必须拿用户原话再比对一次 |

### C. 置信度与信念

| 设计决定 | 来源 | 理由 / 代价 |
|---|---|---|
| 置信度饱和增益（反复说同一件事增益递减） | [17] Zep 时序知识图谱、[18] BELIEFMEM 信念修正 | 防止一句闲聊被说三遍就变成铁律 |
| 证据分级（用户确认 > 模型推断） | [18] + [52][53] 人在回路的选择性写入 | 用户的明确纠正应当压过模型猜测 |
| 单值默认 + 多值白名单兜底，优先信模型 `multi` 标记 | [18] + 问题记录 #2/#5（实测踩坑） | 关系名是动态生成的，靠穷举名单判断必然漏；改成"默认替换、明确多值才共存" |
| 冲突不物理删除旧值，只关 `is_active` 并留来源 | [17][19] 溯源与治理 | 旧信念可能被翻案，留着才能回答"以前以为……" |

### D. 人格与关系

| 设计决定 | 来源 | 理由 / 代价 |
|---|---|---|
| 人格基调慢演化（只在日结移动），即时数值在基调附近摆动 | [12][13] 人格一致性 + [14][15] 人格向量 | 避免每轮对话都把人格改得面目全非 |
| 人格更新准入守卫 `persona_update_allowed` | [16] 角色一致性 + 设计取舍（只有聊到"自我"才允许改） | 事实沉淀和人格演化分开，防止闲聊污染人设 |
| 好感度状态机 + 阈值事件（cold / severed / reconciled） | [20][21] 主动对话综述、[22][23] OCC 情绪模型、[59][61] 社交智能评测 | 数值与状态分离：数值连续变化，状态只在跨阈值时迁移并触发事件 |
| 和解门槛高于转冷门槛 | [62] 依恋理论 + 设计取舍 | 关系破裂后不能"回到不冷"就自动翻篇，要更高的修复成本 |
| 表达分层 warm / neutral / distant | [22][23] 情绪措辞 + 实测（原方案只看两种状态） | 同样的"冷淡"，数值 29 和 5 的语气不该一样 |
| 情绪翻译成"此刻怎么说话"的独立 Prompt 块 | `docs/persona-module-review.md` §5.3（项目自评："被否了却毫无感觉是最不像人的地方之一"）+ [22][23] OCC 情绪措辞 | 裸数字"强度 0.62"模型不知道怎么变成语气；改成"话短一点、会停顿"这类可执行提示。关掉开关可回退对照 |
| 真实事件触发情绪，只改内心不发消息 | 同上 + [63][64] 情感风险 | 信念被推翻/关系转冷由**事件本身**唤起情绪，不靠模型自觉；但绝不自动发消息、不进调度，断交声明仍受 `SEVERANCE_OPT_IN` 约束 |
| 刻意避开"三档记忆确定性"方案 | 用户约束：`belief-system-spec.md` §9–15 重构先跳过 | "朝更像人"不等于改口做整套重构；情绪方案不依赖 `belief_id`/`dormant` 基础设施，改动局部、可独立验证 |
| 久别重逢 = 注入"时间背景"而不是强制客套 | `docs/persona-module-review.md`（"能答出这个月的事"）+ [59][61] 多日社交连续性与陪伴评测 | 系统早记着 `session_store.update_ts` 却没用在回答上，隔三天和隔三分钟一个样；现在按间隔渲染区块、带出上次话题，但明说"不必照念、对方直奔主题就跟上"，避免堆客套 |
| 重逢只改 Prompt、不动状态、不发消息 | 用户约束（延续情绪方案）+ [63][64] 情感风险 | 和情绪方案同一条安全线：她只"表现得像记得时间"，不擅自联系、不改好感/人格；断交仍 opt-in |
| "上次聊的话题"必须按 turn_id 查真实归档 | 问题记录 #21（审查发现用召回话题冒充会编造记忆）+ 思考纪律第 7 条 | 宁可不带这个话题，也不说一个假的"上次你说…"；相关性检索结果不能当历史事实 |
| 时钟可注入（可选 `now` 参数） | 工程约束：离线测试不能依赖真实时钟 | `chat/save/append` 加可选 `now`，缺省走真实时钟（生产不变）；测试注入固定时刻即可确定性断言"隔三天"的反应 |

### E. 可靠性与运维

| 设计决定 | 来源 | 理由 / 代价 |
|---|---|---|
| 任务持久化到 SQLite，`claim` 条件更新防重复兑现 | [41][42] 持久工作流与一致性、[43] 幂等、[44] 重试退避 | 多个 worker 同时跑也只兑现一次；没引入外部队列 |
| 进程内调度默认开启，可切外部 worker | [3] 分级记忆 + [41] 持久队列；实测单进程够用 | 单用户默认零运维；要扩展时关一个配置改用 `scripts/proactive_worker.py` |
| 固定对话回放 + golden 快照 | 问题记录 #11/#13（实测发现盲区） | 测试全绿只证明被测路径没问题；加一条"走真实客户端"的回放才抓到生产 bug |
| 限流从线程锁升级为可选 SQLite 后端 | [45] 滑动窗口、[46] 长尾延迟 + 工程约束（不引 Redis） | 默认行为不变；多进程部署时开 `RATE_LIMIT_BACKEND=sqlite`，用 SQLite 写事务串行化 |

### F. 从 bug 反推出来的设计（踩坑 → 规则）

| 踩过的坑 | 反推出来的规则 |
|---|---|
| 白名单写英文导致中文全漏（#2） | 能由数据自己携带的标记（`multi`）优先；名单只做兜底，且默认行为要安全 |
| `query_by_text` 重复定义（#3） | 一个文件里同名方法只保留最后一个——改完要确认改的是被调用的那个 |
| id 生成两次（#6）、随机 4 位数（#7） | id 只生成一次；用 uuid，不自制生成器 |
| 限流 dict 无锁（#10） | 共享可变状态必须原子化；抽纯函数让并发也能离线测 |
| 测试全用 `client=None` 漏掉生产 bug（#11） | 每层至少有一条"走真实依赖"的测试，降级分支不能替代 |
| `chat()` 入口的 `new_id` 未导入，二次印证（#18） | 主入口函数必须有真正调用它的测试；"从没被直接调用"的代码是最危险的盲区 |
| Prompt 里中文引号写成 ASCII 引号（#19） | Prompt 文本内嵌示例引号一律用「」；写完立刻 `py_compile` |
| `long_hours` 传了秒当小时（#20） | 带单位的参数按单位换算，别凭数字直觉 |
| 召回话题冒充"上次聊的"（#21） | "上次/之前/你曾经…"必须有真实记录撑腰；相关 ≠ 上次 |
| 函数内重复 import 遮蔽 + 异常被吞（#22） | 函数内 import 会让名字在整个函数里变局部变量；降级的 try/except 必须写 `debug["error"]`，不许静默 |
| 情绪重复/名义值/琐事滥情（#23） | 加新层先查旧层是否重复；上报取落库后的真实值；情感挂在已有重要性门槛上 |
| 新配置无校验、UI 开关误伤数值（#24） | 每个新配置都要进 `validate_config`（含 isfinite 挡 nan）；运行时开关只覆盖 bool 键 |
| 情绪增强项无保护（#25） | 新增环节要么可降级、要么别加——失败不能造成"报告失败但半份落库" |
| Windows 临时库删不掉（#12） | 临时 SQLite 库退出前必须 `close_all_connections()` |
| SQLite 按列名取值报 TypeError（#15） | 连接必须设 `row_factory = sqlite3.Row` |
